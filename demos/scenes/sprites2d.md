# sprites2d

A side-scrolling parallax stack: a sun, three full-screen hill layers whose uv scrolls at 0.15, 0.4 and 0.8 of the
camera and 65 sprites in front of each hill drifting at that hill's parallax, 199 instanced quads from
`shaders/sprite2d.vert` + `shaders/sprite2d.frag`, alpha-blended back to front over a sky-blue clear and tinted by a
sunset colour. The scene is laid out in 1280x720 pixels and drawn at any target size (`core/src/gpu/demo_sprites.rs`,
1920x1080 in the window, 320x180 in its test). Conventions and `(verify)` meaning as in pbr-boombox.md.

## Guest memory map

One contiguous mapping, because a draw whose programs read guest memory binds a global window over all of it.

| VA | size | contents |
|---|---|---|
| 0x1000_0000 | 0x1_0000 | pushbuffer: init +0x0000, per frame +0x8000 |
| 0x1001_0000 | 0x1_0000 | sprite2d.vert program +0x0000, sprite2d.frag program +0x8000 |
| 0x1002_0000 | 0x1_0000 | VS bank 0x1d +0x0000, camera +0x1000 (16 B), PS bank 0x1d +0x2000, tint +0x3000 (16 B) |
| 0x1003_0000 | 0x1_0000 | TIC pool +0x0000 (1 entry), TSC pool +0x8000 (1 entry) |
| 0x1004_0000 | 0x1_0000 | instance buffer, 199 x 48 B |
| 0x1005_0000 | 0x4_0000 | atlas, 256x256 RGBA8 pitch 1024, mip 0 only |
| 0x1009_0000 | width x height x 4 | colour target, A8B8G8R8 pitch width x 4 |

The atlas is generated by the host at init, so there is no asset file: rows 64k..64k+63 for k = 0, 1, 2 hold a hill
silhouette (opaque below `y = 32 + (10 + 6k) sin(2 pi (k + 1) x / 256)` within the row, transparent above, colour
darkening with k so the near layer is darkest); row 192..255 holds four 64x64 sprite cells (yellow disc, red ring,
white star, blue diamond) with antialiased alpha edges. Horizontal wrap is seamless because each sine has a whole
number of periods across 256 texels.

## Instances (48 bytes each: transform, uv_rect, layer)

| instance | transform (cx, cy, hx, hy) px | uv_rect (u, v, du, dv) | layer (pos parallax, uv parallax, rotation, alpha) |
|---|---|---|---|
| 0, sun | 1080, 90, 48, 48 | 0, 0.75, 0.25, 0.25 | 0, 0, 0, 0.8 |
| 1 + 66k, hill k | 640, 520 / 560 / 620, 640, 200 / 160 / 100 | 0, 0.25k, 3.0 - 0.5k, 0.25 | 0, 0.15 / 0.4 / 0.8, 0, 1 |
| the 65 after hill k | x wrapped across the screen, y = 160..460 bobbing, h = (6 + 6k)..(9.6 + 9.6k) | cell (i mod 4) * 0.25, 0.75, 0.25, 0.25 | hill k's parallax, 0, spinning, 0.6 + 0.175k |

uv_rect heights of 0.25 select one atlas row; widths above 1 repeat the row across the screen through the wrap mode.
The host rewrites the instance buffer before each frame's submit: it wraps each sprite's x back across the screen and
adds the parallax scroll the vertex program subtracts, bobs y and advances the rotation.

## Pools and the driver bank

TIC 0, the atlas: 0x58d24908 0x10050000 0x00400000 0x00000020 0x008000ff 0x800000ff 0 0 (A8B8G8R8 UNORM, verify).
TSC 0, repeat, nearest, no mip: 0x00000000 0x00000051 0 0 0 0 0 0.

Neither program reads c0..c2. Both read their binding 1 block through the bindless cbuf handle in bank 0x1d at +0x8
(`ULDC.64 UR4, c[0x1d][0x8]`, vert.sass 0x30 and frag.sass 0x80), and the pixel program takes its texture handle from
bank 0x1d +0x0 (`TEX.SCR ... 0x1d, 0x0`, frag.sass 0x60). So the VS bank holds 0, 0, camera >> 4, 1 << 13 and the PS bank
0x00000000 (TIC 0, TSC 0), 0, tint >> 4, 1 << 13: a handle is the address >> 4 in bits 0..45 and the size >> 4 above.

## Uniforms

Camera: (scroll x px, scroll y px, 2/1280, 2/720); per frame only word 0 changes (scroll x += 120 px/s). Tint:
(1, 0.9, 0.8, 1), written once.

49 and 51-52, its texture pools as rows 64-65 with max index 0, no depth target, and:

The rig's programs stop at their last EXIT, so the host appends the self-branch a compiled program ends with. The
register counts are not in the rig output and nothing here reads them, so the init program leaves them out.

## Per-frame program (subchannel 0)

| # | method | offset | value | meaning |
|---|---|---|---|---|
| 1 | SET_CONSTANT_BUFFER_SELECTOR_A / B / C / LOAD_CONSTANT_BUFFER_OFFSET | 0x2380-0x238c | 16 / 0 / 0x10021000 / 0 | select the camera |
| 2 | LOAD_CONSTANT_BUFFER (0) | 0x2390 | scroll x as f32 | camera scroll |
| 3 | CLEAR_SURFACE | 0x19d0 | 0x0000003c | clear RGBA to the sky colour |
| 4 | DRAW_VERTEX_ARRAY_BEGIN_END_INSTANCE_FIRST | 0x1214 | 0x50040000 | triangle strip, 4 vertices, instance 0 |
| 5 | DRAW_VERTEX_ARRAY_BEGIN_END_INSTANCE_SUBSEQUENT, non-incrementing packet of 198 | 0x1218 | 0x50040000 each | instances 1-198, coalesced into one instanced draw in order |

## What the pipeline must provide

Per-instance vertex streams, alpha blending with separate alpha factors, repeat-wrap nearest sampling, bindless cbuf
reads through the global window, and instance order preserved when the FIRST + SUBSEQUENT draws are coalesced
(blending makes order visible).
